Conceito

Um arquivo descreve os três serviços

1
bancoa imagem oficial do MySQL, com usuário, senha e um volume para os dados
2
apiuma imagem feita a partir do backend/, por um Dockerfile
3
webo Caddy com o build do React dentro, na porta 8080
O docker-compose.yml descreve os serviços. Com o Docker Compose instalado e as variáveis preenchidas, vocês iniciam o projeto pelo docker compose up.

Leitura linha a linha

O Dockerfile é a receita da imagem

exemplo do professor · backend/Dockerfile
# a imagem oficial do Python, na versão enxuta
FROM python:3.12-slim
# a pasta de trabalho dentro da imagem
WORKDIR /app
# primeiro a lista de bibliotecas: o Docker reaproveita esta etapa
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
# depois o resto do código
COPY . .
# modo de produção, atendendo em 0.0.0.0 na porta 8000
CMD ["fastapi", "run", "main.py", "--port", "8000"]

Python que faltava

Salvar a lista de bibliotecas

terminal · dentro de backend/, com o venv ativo
pip freeze > requirements.txt
  1. No terminal do backend/, ativar o venv do projeto.
  2. Executar pip freeze > requirements.txt. O > grava a lista no arquivo.
  3. Abrir o requirements.txt e conferir as bibliotecas e suas versões. A imagem vai instalar essa lista.

Sem o venv ativo, o pip freeze pode listar bibliotecas que não pertencem ao projeto.

O que não entra na imagem

O .dockerignore

backend/.dockerignore
venv/
.env
__pycache__/
frontend/.dockerignore
node_modules/
dist/
  1. O venv/ e o node_modules/ foram montados no Windows. A imagem é Linux e instala os dela.
  2. O .env pode conter senhas. Se entrar na imagem, quem tiver acesso a ela poderá ler o arquivo.

Leitura linha a linha

A tela é construída em duas etapas

exemplo do professor · frontend/Dockerfile
# etapa 1: uma imagem com Node só para gerar o build
FROM node:22 AS build
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
RUN npm run build
# etapa 2: o Caddy, levando só o dist/ da etapa 1
FROM caddy:2
COPY --from=build /app/dist /srv

O Node fica na etapa de build. A imagem final usa o Caddy para servir a tela, como na aula 2.

Leitura linha a linha

O docker-compose.yml

o banco
services:
  banco:
    image: mysql:8.4
    environment:
      MYSQL_DATABASE: tarefas
      MYSQL_USER: app
      MYSQL_PASSWORD: ${SENHA_DO_BANCO}
      MYSQL_ROOT_PASSWORD: ${SENHA_DO_BANCO}
    volumes:
      - dados_do_banco:/var/lib/mysql
a API e o Caddy
  api:
    build: ./backend
    environment:
      URL_DO_BANCO:
        mysql+mysql...@banco:3306/tarefas
      CHAVE_DO_TOKEN: ${CHAVE_DO_TOKEN}
  web:
    build: ./frontend
    ports: ["8080:80"]
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile

Trechos para leitura. O prompt do slide 13 gera o arquivo completo.

Conceito

Na rede do Compose, usem o nome do serviço

Quem chamaAntesNo compose
A API chama o bancolocalhost:3306banco:3306
O Caddy chama a APIhost.docker.internal:8000api:8000
Dentro do contêiner da API, localhost aponta para a própria API. Para acessar o MySQL, usem banco.

No Caddyfile, o destino passa a ser reverse_proxy api:8000.

Senha fora do Git

O compose lê um .env na raiz

.env · fora do Git
SENHA_DO_BANCO=uma-senha-forte
CHAVE_DO_TOKEN=4f9c1e...
.env.exemplo · vai para o Git
SENHA_DO_BANCO=
CHAVE_DO_TOKEN=
  1. O ${SENHA_DO_BANCO} do compose é trocado pelo valor desse .env na hora do up.
  2. A API recebe o URL_DO_BANCO do compose. O .env do backend/ não entra na imagem.
  3. Conferir o .gitignore da raiz. a linha .env cobre esse arquivo também.

Conceito

O volume guarda os dados fora do contêiner

Sem volumeSem armazenamento persistente configurado, recriar o contêiner pode fazer vocês perderem os dados.
Com dados_do_bancoOs dados ficam num volume do Docker. Ao recriar o contêiner com o mesmo volume, o MySQL encontra os dados.
docker compose down -v apaga os volumes. Sem o -v, os dados ficam.

Mão na massa · passo 3 de 4

Subir tudo com um comando

terminal · na raiz do repositório
docker compose up -d --build
  1. Parar o fastapi dev e o Caddy da aula 2. A porta 8080 precisa estar livre.
  2. Na raiz do repositório, executar o comando. Na primeira vez, o Docker baixa as imagens e instala as dependências.
  3. Executar docker compose ps. Os três serviços aparecem como Up.

O -d deixa os serviços em segundo plano. Up indica que o contêiner está rodando, mas o MySQL ainda pode estar iniciando.

  1. Na raiz do repositório, executar o primeiro comando. Ele cria as tabelas dentro do banco novo.
  2. Se a criação das tabelas terminou sem erro, executar o segundo comando. Ele registra a versão atual das migrations.
  3. Abrir http://localhost:8080. Cadastrar e testar um usuário de cada perfil.

Os comandos do compose

ComandoO que faz

docker compose psmostra os serviços e o estado de cada um
docker compose logs apimostra o que a API escreveu no terminal dela

Depois de alterar o código, rodem docker compose up -d --build para atualizar as imagens e os contêineres.

Demonstração · passo 1 de 4

Criar a máquina na AWS

  1. No console da AWS, abrir EC2 e Executar instância. Imagem: Ubuntu 24.04.
  2. Selecionar o tipo t3.small, com 2 GB de memória. Com 1 GB, pode faltar memória durante o build do front.
  3. Criar um par de chaves e baixar o arquivo .pem. Ele é a chave de entrada.
  4. No grupo de segurança, liberar a porta 22 só para o IP de quem administra, e as portas 80 e 443 para todos.
  5. Anotar o IPv4 público da instância quando ela aparecer como Executando.

Conceito

Acessem o terminal do servidor com SSH

PowerShell · na pasta onde está o .pem
ssh -i tarefa-certa.pem ubuntu@IP-PUBLICO
  1. O SSH abre um terminal do servidor dentro do terminal de vocês. Tudo passa cifrado, pela porta 22.
  2. A chave .pem autentica o acesso. Quem tiver a chave pode entrar nas instâncias que a aceitam.
  3. O ubuntu é o usuário padrão da imagem do Ubuntu na AWS.

Guardem o .pem fora da pasta do projeto. Não enviem a chave para o Git ou o Teams.

Permissões da chave no Windows

O SSH pode recusar as permissões da chave

PowerShell · quando aparecer "UNPROTECTED PRIVATE KEY FILE"
icacls tarefa-certa.pem /inheritance:r
icacls tarefa-certa.pem /grant:r "$($env:USERNAME):(R)"
  1. Conferir se o erro é UNPROTECTED PRIVATE KEY FILE. O arquivo pode ter permissões herdadas para outros usuários.
  2. No PowerShell, na pasta do .pem, executar os dois comandos. Eles removem a herança e permitem a leitura pelo usuário atual.
  3. Tentar o SSH de novo. Se o erro continuar, chamar o professor para conferir as permissões que ainda ficaram no arquivo.

Demonstração · passo 3 de 4

Configurar o subdomínio e o HTTPS

Caddyfile no servidor
tarefas.seudominio.com.br {
    handle_path /api/* {
        reverse_proxy api:8000
    }
    handle {
        root * /srv
        file_server
    }
}
serviço web no compose
  web:
    build: ./frontend
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile
      - certificados:/data

Antes do up, apontar o registro A para o IP público e conferir as portas 80 e 443. O Caddy tenta emitir o certificado.

Demonstração · passo 4 de 4

Subir e conferir o HTTPS

  1. No servidor, executar docker compose up -d --build, como no primeiro tempo.
  2. Criar as tabelas e marcar as migrations com os dois docker compose exec.
  3. Ler o docker compose logs web. O Caddy registra o certificado obtido.
  4. Abrir o domínio configurado por HTTPS. Conferir se o navegador aceita o certificado e testar o login.

O volume certificados mantém os certificados ao recriar o contêiner. Sem ele, novas emissões podem atingir os limites da autoridade certificadora.

Custos da demonstração

O que continua sendo cobrado

  1. Interromper uma instância sob demanda para a cobrança de processamento. Discos e outros recursos podem continuar cobrados.
  2. Ao iniciar de novo, o IPv4 público automático pode mudar. Confiram o endereço e atualizem o registro do subdomínio.
  3. Encerrar remove a instância. A exclusão de cada disco depende da configuração dele. Confiram os dados antes de encerrar.
  4. Configurem um alerta de orçamento. O aviso pode atrasar e não bloqueia os gastos por si só.

Recapitulando

O que vocês fizeram hoje

  • O Dockerfile é a receita de uma imagem. O docker-compose.yml junta os serviços.
  • Na rede do Compose, a API usa banco e o Caddy usa api como endereço.
  • Senha fica no .env, fora do Git e fora da imagem. Dados ficam num volume.
  • Na EC2, vocês configuram o sistema, o Docker e o acesso por SSH. Também acompanham os custos.
  • Com DNS e portas configurados, o Caddy emite e renova o certificado do domínio.
