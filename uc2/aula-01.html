Conceito

Cliente pede, servidor atende

C
ClienteInicia a comunicação. O navegador pede uma página ou chama a API.
S
ServidorRecebe pedidos em uma porta. A API de vocês atende na 8000.
O notebook pode executar um servidor. Quando vocês iniciam o Uvicorn, ele passa a receber pedidos na porta 8000.

O endereço do prédio

Encontrem o IP da máquina de vocês

terminal · no Windows
ipconfig

# Adaptador Ethernet:
#    Endereço IPv4. . . . . . . : 192.168.0.23
  1. No terminal, rodem ipconfig. No Linux, usem ip -4 addr.
  2. Procurem o Endereço IPv4 do adaptador conectado à rede.
  3. Anotem esse IP. Ele será usado nos testes dos próximos slides.

192.168.x.x é uma faixa privada. O mesmo endereço pode existir em outra rede. Ele não dá acesso direto pela internet.

O número da sala

As portas usadas nesta aula

PortaQuem costuma atender
80site em HTTP, sem cadeado
443site em HTTPS, com cadeado
5173o Vite, servindo o React em desenvolvimento
8000o uvicorn, servindo a sua API
3306o MySQL

Duas APIs tentando usar o mesmo IP e a mesma porta TCP dão conflito. Escolher outro IP ou outra porta muda a situação.

Conceito

Em quais endereços a API atende?

o padrão do fastapi dev
fastapi dev main.py
# Server started at
#   http://127.0.0.1:8000

# acesso pelo IP da rede:
# ERR_CONNECTION_REFUSED
aberta para a rede
fastapi dev main.py --host 0.0.0.0
# Server started at
#   http://0.0.0.0:8000

# acesso pelo IP da rede:
# {"status":"ok"}

127.0.0.1 atende só na própria máquina. 0.0.0.0 escuta em todas as interfaces IPv4. No navegador, usem o IP da máquina.

O cadeado

HTTPS protege os dados no caminho

HTTP, porta 80
# o que passa pelo wi-fi
GET /tarefas
Authorization: Bearer eyJhbGci...
# legível para quem intercepta o tráfego HTTP
HTTPS, porta 443
# o que passa pelo wi-fi
17 03 03 00 4a 9f c2 51
e8 0b 7d 33 a1 6c f0 2e
# tráfego cifrado entre navegador e servidor
HTTPS cifra o tráfego entre navegador e servidor. Em HTTP, quem consegue interceptar o tráfego pode ler a senha ou o token.

Segundo tempo

O seu projeto em outra máquina

O servidor do desenho ainda precisa do Python e das dependências do projeto. Vocês teriam que preparar esse ambiente em cada máquina.

Como repetir o ambiente do projeto em outra máquina sem refazer a instalação de cada dependência?

A dor do segundo tempo

"Na minha máquina funciona"

exemplo do professor · preparar outra máquina para o Tarefa Certa
1. instalar o Python e criar o venv
2. instalar as bibliotecas certas    # quais? qual versão?
3. instalar o Node e rodar npm install

Uma versão diferente do Python ou uma dependência ausente já pode impedir a execução. O servidor também precisa de um ambiente compatível.

Onde paramos

O que o venv isola?

O venv guardaAs bibliotecas Python do projeto, separadas das de outros ambientes. Ele usa o Python escolhido na criação.
O venv não guardaO Node, o servidor MySQL e o sistema operacional. Copiar a pasta do venv não recria esse ambiente em outra máquina.
Com Docker, podemos empacotar o programa e suas dependências. Os dados do banco precisam de armazenamento próprio.

Um pouco de história

De onde vem a ideia do contêiner?

1956, no portoMalcom McLean usou caixas de carga no navio Ideal X. A caixa permitia transferir a carga entre caminhão e navio sem manusear cada item.
2013, no softwareO Docker foi apresentado na PyCon. A imagem reúne o programa e os arquivos de que ele precisa para rodar em um contêiner.

A caixa de carga é uma analogia. O contêiner de software executa um processo isolado e compartilha o núcleo do sistema.

Conceito, com o que você já sabe

Imagem e contêiner

No PythonNo Docker
class Tarefa, o moldea imagem, guardada no disco
Tarefa(titulo="...")o contêiner, uma instância da imagem
três objetos da mesma classetrês contêineres criados da mesma imagem
pip baixa do PyPIdocker baixa do Docker Hub

Classe e objeto ajudam na comparação. A imagem é o modelo; o contêiner tem estado e pode estar em execução ou parado.

Contêineres Linux compartilham um núcleo Linux. Na instalação que vamos usar no Windows, esse núcleo é fornecido pelo WSL 2.

Instalação · passo 1 de 3

O WSL 2 primeiro

PowerShell · aberto como administrador
wsl --version    # precisa ser 2.1.5 ou maior
wsl --install    # se o comando de cima falhar
wsl --update     # se a versão for menor
  1. Confiram os requisitos no guia do Docker para Windows. São necessários 8 GB de RAM e virtualização habilitada.
  2. Abram o PowerShell em Executar como administrador. No laboratório, chamem o professor.
  3. Rodem wsl --version. A versão do WSL precisa ser 2.1.5 ou maior.
  4. Se faltar WSL, usem wsl --install. Se estiver antigo, usem wsl --update. Reiniciem se solicitado.

Antes de seguir, rodem wsl --version novamente e confiram a versão.

Instalação · passo 2 de 3

O Docker Desktop

  1. No guia docs.docker.com/desktop/setup/install/windows-install/, baixem o instalador para a arquitetura da máquina.
  2. Executem o instalador. Escolham WSL 2 como backend se essa opção aparecer.
  3. Ao terminar, abram o Docker Desktop pelo menu Iniciar.
  4. Leiam e aceitem os termos. O login é opcional.
  5. Esperem o Docker Desktop indicar que o mecanismo está em execução.

No Mac, usem o instalador para o chip da máquina. No Linux, sigam o guia oficial do Docker Engine.

O primeiro contêiner

terminal · qualquer pasta

  1. Abram um terminal novo depois da instalação para carregar o caminho do docker.

Leitura linha a linha

O que o hello-world fez

a saída do docker run hello-world, resumida
Unable to find image 'hello-world:latest' locally  # imagem ausente nesta máquina
Pulling from library/hello-world                   # baixou do Docker Hub
Hello from Docker!                                 # o contêiner executou
  1. No terminal, rodem docker images. Procurem a imagem hello-world.
  2. Rodem docker ps -a. O contêiner aparece com Exited. Ele imprimiu a mensagem e terminou.
  3. Rodem docker run hello-world de novo e confiram docker ps -a. Deve aparecer outro contêiner.

Recapitulando

O que fica da aula 1

  • O notebook de vocês pode executar servidores. A API atende na porta 8000.
  • Na analogia, IP é o endereço e porta é a sala. 127.0.0.1 aponta para a própria máquina.
  • O React roda no navegador do usuário. Um fetch para localhost procura a API na máquina desse usuário.
  • No plano de hoje, a aplicação recebe HTTPS na 443. A API e o banco ficam na rede interna.
  • A imagem reúne os arquivos do programa. O contêiner é uma instância isolada que pode executar esse programa.

Na próxima etapa, vamos configurar o servidor web que entrega a tela e encaminha os pedidos da API.
