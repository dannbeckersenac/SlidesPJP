A analogia de hoje

A rede é uma rua cheia de prédios

Na ruaNa rede
o prédiouma máquina: o seu notebook, um servidor
o endereço do prédioo IP
a sala, com o número na portaa porta: 8000, 5173, 3306
"aqui dentro deste prédio"localhost, ou 127.0.0.1
o nome salvo na agenda do celularo domínio, que o DNS traduz em IP

Conceito

Cliente pede, servidor atende

C
ClienteQuem toma a iniciativa: o navegador, o app do celular. Bate na porta de uma sala e espera.
S
ServidorUm programa parado numa porta, esperando alguém bater. Atende, responde e volta a esperar.
Servidor é um papel, não um tipo de computador. O seu notebook já é servidor: o uvicorn está esperando na porta 8000.

O endereço do prédio

O IP da sua máquina

terminal · no Windows
ipconfig

# Adaptador Ethernet:
#    Endereço IPv4. . . . . . . : 192.168.0.23
  1. Abra um terminal e rode ipconfig. No Linux é ip -4 addr.
  2. Ache a linha Endereço IPv4 do adaptador que está ligado na rede.
  3. Anote o número. Ele é o endereço do seu prédio dentro da rede do laboratório.

Repare: todo IP que começa com 192.168 só vale dentro desta rede. De casa, ninguém chega nele.

O número da sala

Uma máquina, vários programas, cada um na sua porta

PortaQuem costuma atender
80site em HTTP, sem cadeado
443site em HTTPS, com cadeado
5173o Vite, servindo o React em desenvolvimento
8000o uvicorn, servindo a sua API
3306o MySQL

Duas salas com o mesmo número não existem: subir a API duas vezes dá erro de porta em uso.

Conceito

A sua API só atende quem está dentro

o padrão do fastapi dev
fastapi dev main.py
# Server started at
#   http://127.0.0.1:8000

# o colega, pelo seu IP:
# ERR_CONNECTION_REFUSED
aberta para a rede
fastapi dev main.py --host 0.0.0.0
# Server started at
#   http://0.0.0.0:8000

# o colega, pelo seu IP:
# {"status":"ok"}

Na rua de prédios: 127.0.0.1 é a sala que só atende o interfone de dentro. 0.0.0.0 atende também quem chega pela rua.

O cadeado

Lembra do token do login?

HTTP, porta 80
# o que passa pelo wi-fi
GET /tarefas
Authorization: Bearer eyJhbGci...
# qualquer um na rede lê
HTTPS, porta 443
# o que passa pelo wi-fi
17 03 03 00 4a 9f c2 51
e8 0b 7d 33 a1 6c f0 2e
# só o servidor decifra
Em localhost, o pedido nem sai do notebook. Em produção, login sem HTTPS é entregar o token para a rede inteira.

Segundo tempo

O seu projeto em outra máquina

O desenho tem um servidor em algum lugar. Esse servidor é um prédio que nunca viu o seu projeto. Alguém vai ter que montar tudo lá dentro.

A pergunta do segundo tempo: como levar o projeto inteiro para um prédio novo sem montar tudo de novo, peça por peça?

A dor do segundo tempo

"Na minha máquina funciona"

exemplo do professor · o que o colega precisa para rodar o Tarefa Certa
1. instalar o Python e criar o venv
2. instalar as bibliotecas certas    # quais? qual versão?
3. instalar o Node e rodar npm install
4. instalar o MySQL 8 e criar usuário, senha e banco
5. escrever o .env com a URL do banco e a chave do token
6. alembic upgrade head

Cada linha é uma chance de dar diferente: outro Python, MySQL 5.7, senha errada. E o servidor de produção é só mais uma máquina que precisa da lista inteira.

Onde paramos

O venv isola pouco

O venv guardaAs bibliotecas Python deste projeto: fastapi, sqlalchemy, pwdlib. Só isso.
O venv não guardaA versão do Python, o Node, o MySQL com o banco criado e o próprio sistema operacional.
O que falta levar é a máquina inteira, do sistema ao banco. É isso que o contêiner leva junto.

Um pouco de história

O problema já foi resolvido uma vez, no porto

1956, no portoCada carga ia de um jeito: saco, barril, caixote. Carregar um navio levava dias. Malcom McLean padronizou a caixa de metal, e qualquer navio, guindaste ou caminhão passou a carregar sem abrir.
2013, no softwareO Docker foi apresentado numa palestra de cinco minutos na PyCon. A ideia era a mesma: uma caixa padrão, com o programa e tudo de que ele precisa dentro.

Na rua de prédios: o contêiner é uma sala que muda de prédio já montada, com os móveis dentro.

Conceito, com o que você já sabe

Imagem é a classe, contêiner é o objeto

No PythonNo Docker
class Tarefa, o moldea imagem, guardada no disco
Tarefa(titulo="...")o contêiner, uma cópia rodando
três objetos da mesma classetrês contêineres da mesma imagem
pip baixa do PyPIdocker baixa do Docker Hub

Por isso: apagar o contêiner não apaga a imagem, do mesmo jeito que apagar um objeto não apaga a classe.

Conceito

Contêiner não é máquina virtual

Máquina virtualContêiner
Leva juntoum sistema operacional inteiroo programa e o que ele usa
Tamanhogigabytesmegabytes
Para ligarminutossegundos
O contêiner divide o núcleo do sistema com a máquina. No Windows, o núcleo Linux vem do WSL 2, e é por isso que ele entra na instalação.

Instalação · passo 1 de 3

O WSL 2 primeiro

PowerShell · aberto como administrador
wsl --version    # precisa ser 2.1.5 ou maior
wsl --install    # se o comando de cima falhar
wsl --update     # se a versão for menor
  1. Confira: Windows 10 22H2 ou Windows 11, com 8 GB de memória.
  2. Abra o PowerShell com o botão direito, em Executar como administrador.
  3. Rode wsl --version. Se a versão for 2.1.5 ou maior, pule para o próximo slide.
  4. Senão, rode wsl --install ou wsl --update. Reinicie se ele pedir.

No laboratório: se pedir senha de administrador, chame o professor.

Instalação · passo 2 de 3

O Docker Desktop

  1. Baixe o Docker Desktop Installer.exe em docs.docker.com/desktop.
  2. Rode o instalador e deixe marcado Use WSL 2 instead of Hyper-V.
  3. No fim, clique em Close. Ele não abre sozinho: abra pelo menu Iniciar.
  4. Aceite os termos. O login é opcional: pode pular.
  5. Espere o canto inferior esquerdo mostrar Engine running.

Fora do Windows: no Mac é o mesmo Docker Desktop, escolhendo chip Apple ou Intel. No Linux, siga o guia do Docker Engine no site oficial.

Instalação · passo 3 de 3

O primeiro contêiner

terminal · qualquer pasta
docker --version
docker run hello-world
  1. Abra um terminal novo. O que já estava aberto não conhece o comando docker.
  2. Rode docker --version. Qualquer versão serve.
  3. Rode docker run hello-world.
  4. Deu certo se aparecer Hello from Docker! no meio do texto.

Leitura linha a linha

O que o hello-world fez

a saída do docker run hello-world, resumida
Unable to find image 'hello-world:latest' locally  # não tinha a classe
Pulling from library/hello-world                   # baixou do Docker Hub
Hello from Docker!                                 # o objeto rodou
  1. Rode docker images. A imagem hello-world está na lista, guardada no disco.
  2. Rode docker ps -a. Tem um contêiner com Exited: ele rodou, escreveu e terminou.
  3. Rode docker run hello-world de novo. Desta vez não baixa nada, e a lista do ps -a ganha mais um.

Recapitulando

O que fica da aula 1

  • Servidor é um programa esperando numa porta. O seu notebook já é um.
  • IP é o prédio, porta é a sala, DNS é a agenda. 127.0.0.1 é sempre a máquina de quem pede.
  • O React roda no navegador de quem abre. Por isso o fetch no 127.0.0.1 falha nos outros.
  • Em produção, só a 443 abre para a rua, e com cadeado.
  • Imagem é a classe, contêiner é o objeto. O contêiner leva a máquina junto.
