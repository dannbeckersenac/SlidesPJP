A dor

Copiar do chat dá trabalho

  1. Copiar a descrição da tarefa.
  2. Abrir o chat e colar junto com o pedido.
  3. Ler a resposta e copiar as etapas.
  4. Voltar ao sistema e digitar uma por uma.
Queremos que o sistema envie a descrição e receba as etapas. O executor continua conferindo a resposta.

Conceito

O que um modelo de linguagem faz

O modelo foi treinado com muitos textos. Ele usa o texto recebido para gerar uma continuação.

Não acessa o bancoNeste teste, ele recebe só o pedido. Não consulta as tarefas no banco de vocês.
Erra com confiançaEle pode escrever uma resposta errada com toda a certeza. Vocês precisam conferir.
Pode variarA mesma entrada pode gerar respostas diferentes. Vamos repetir os testes para comparar.

Conceito

A chave identifica o projeto de vocês

A chave identifica o projeto no Google. Os pedidos descontam da cota desse projeto.

Quem tiver a chave pode consumir a cota do projeto. Guardar no backend, como a CHAVE_DO_TOKEN.

O limite de pedidos é por projeto. Criar outra chave no mesmo projeto não aumenta a cota. Conferir os limites em aistudio.google.com/rate-limit.

Mão na massa · passo 1 de 8

Criar a chave no Google AI Studio

  1. Abrir aistudio.google.com/apikey e entrar com a conta do Google.
  2. Clicar em Create API key e seguir as instruções para criar a chave num projeto.
  3. Copiar a chave.
  4. Guardar a chave em local privado, fora de conversas com a IA e de prints.

Quem não conseguir criar a conta recebe a chave com o professor.

Mão na massa · passo 2 de 8

Conhecer o AI Studio antes do código

  1. No AI Studio, abrir a área de testes (Playground) e colar o pedido do seu .docs/ia.md.
  2. Trocar o modelo na lista e comparar as respostas.
  3. Clicar em Get code e ver o mesmo pedido escrito em Python.
  4. Abrir aistudio.google.com/rate-limit e conferir os limites do plano grátis do seu projeto.

O Playground também usa a cota do projeto. Testar a ideia ali antes de escrever código poupa tempo.

Segurança

O que acontece com os dados enviados

No plano grátis, o Google usa os pedidos e as respostas para melhorar os produtos. Pessoas podem ler esse conteúdo.

Usar só dados fictícios nos testes, como os das cartilhas. Os termos proíbem enviar dados pessoais ou confidenciais no plano grátis.

No plano pago, os pedidos não são usados para melhorar os produtos. Essa diferença precisa ser explicada antes de usar dados reais.

Mão na massa · passo 5 de 8

Fazer o primeiro pedido

backend/testar_ia.py
from google import genai
import configuracao

# o cliente da API do Gemini, com a chave do .env
cliente = genai.Client(api_key=configuracao.chave_do_gemini)
resposta = cliente.interactions.create(
    model="gemini-3.8-flash", input="Explique em uma frase o que é uma API.")
print(resposta.output_text)
  1. Criar o arquivo backend/testar_ia.py e colar o código.
  2. No terminal, dentro de backend/ e com o venv ativo, executar python testar_ia.py.
  3. Conferir a resposta no terminal. Se aparecer um erro, consultar o próximo slide.

Conceito

Um orquestrador na frente dos provedores

O Jangada é uma biblioteca Python que fica na frente dos SDKs. O mesmo código fala com Gemini, Claude, OpenAI e outros.

O que ganhaTrocar de provedor numa linha. Reserva e tools escritas do mesmo jeito para todos, como vamos ver amanhã.
O que custaMais uma dependência no projeto. Embaixo continua o SDK de cada provedor, e os erros vêm de lá.

Mão na massa · passo 7 de 8

Fazer o mesmo pedido pelo Jangada

backend/testar_jangada.py
from jangada_ai import LLM
import configuracao

# o provedor e o modelo são os dois primeiros argumentos
llm = LLM("gemini", "gemini-3.8-flash", api_key=configuracao.chave_do_gemini)
resposta = llm.complete("Explique em uma frase o que é uma API.")
print(resposta.provider, "respondeu:", resposta.text)
  1. Criar o arquivo backend/testar_jangada.py e colar o código.
  2. No terminal, executar python testar_jangada.py.
  3. Conferir a linha que começa com gemini respondeu:.

Mão na massa · passo 8 de 8

Mandar o pedido do ia.md pelo Jangada

exemplo do professor · backend/testar_jangada.py · no fim do arquivo
# o papel e as regras: o pedido que ficou no .docs/ia.md
INSTRUCAO = """Sugira de 3 a 6 etapas para o checklist desta tarefa.
Responda com uma etapa por linha, começando com um verbo.
Se faltar informação, peça mais detalhes em vez de inventar."""
# o caso de agora: trocar a cada teste
ENTRADA = "Tarefa: Trocar o toner da impressora que está imprimindo falhado."

resposta = llm.complete(ENTRADA, system=INSTRUCAO)
print(resposta.text)
  1. Colar o bloco no fim do arquivo e trocar os textos pelos do seu ia.md.
  2. Executar de novo e conferir se a resposta segue o formato combinado.
