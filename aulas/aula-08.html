Conceito

Hash, e não criptografia

1
Criptografia: um cofreFecha com uma chave e abre com ela. Quem tem a chave lê a senha. Se a chave vaza, vazam todas.
2
Hash: a impressão digitalConfere se é a mesma pessoa, mas não reconstrói a pessoa. Não tem chave, não tem volta.
O banco guarda a digital da senha. Nem você, olhando a tabela, descobre qual era.

Conceito

Então como o login confere?

No cadastroA senha vira digital, e só a digital vai para o banco.
→
No loginA senha digitada passa pela mesma máquina de digital.
→
A comparaçãoAs duas digitais batem? Então a senha é a mesma.

Esqueci a senha? Por isso nenhum sistema sério manda a sua senha por e-mail: ele não tem. Ele manda um link para criar outra.

Conceito

Não serve qualquer hash

O problemaO que o argon2 faz
MD5 e SHA-256 são rápidos: dá para testar bilhões de senhas por segundoé lento de propósito, e gasta memória a cada conta
a mesma senha daria a mesma digital, e quem descobre uma descobre todas iguaismistura um sal sorteado: a mesma senha dá digitais diferentes
o sal precisaria ficar guardado em algum lugaro sal vai dentro do próprio hash, no texto que o banco guarda

O argon2 venceu a competição de hash de senha de 2015. É o que a biblioteca usa por padrão.

Conceito

O token é a pulseira do evento

Na entradaVocê mostra o documento uma vez: o login, com e-mail e senha.
→
A pulseiraSai com o seu número, a hora em que vence e um lacre que ninguém copia.
→
Em cada portaVocê só mostra a pulseira. A porta confere o lacre, e não o documento.

A pulseira vence. O token do exemplo vale uma hora. Depois, novo login.

Conceito

O JWT por dentro: três partes e dois pontos

eyJhbGciOiJIUzI1NiJ9 . eyJzdWIiOiI0IiwiZXhwIjoxNzkxMzA1NzE3fQ . h7vX9f8h6Ds8

ParteO que tem
cabeçalhoo algoritmo da assinatura: HS256
conteúdo{"sub": "4", "exp": 1791305717}: quem é, e quando vence
assinaturao lacre, feito com a chave secreta que só a API tem
O conteúdo é só codificado, qualquer um lê. Nunca ponha senha no token. O que impede a falsificação é a assinatura.

Conceito

Duas perguntas, dois status

A perguntaQuando falha
Autenticaçãoquem é você?401: sem token, token falso ou vencido
Autorizaçãovocê pode fazer isto?403: sei quem você é, e a resposta é não
A Júlia logada tentando lançar um item: sabemos quem é, e ela não pode. É 403, não 401.

Na pulseira: sem pulseira, você nem entra no evento. Com a pulseira verde, você não entra no camarim.

Leitura linha a linha

Fabricar a pulseira

backend/seguranca.py · os imports no topo, a função no fim
from datetime import datetime, timedelta, timezone   # data com hora, e uma duração
import jwt
from configuracao import obter_configuracao
configuracao = obter_configuracao()

def criar_token(usuario_id: int):
    validade = datetime.now(timezone.utc) + timedelta(minutes=60)  # agora mais uma hora
    dados = {"sub": str(usuario_id), "exp": validade}         # quem é, e quando vence
    return jwt.encode(dados, configuracao["chave_do_token"], algorithm="HS256")

sub e exp são nomes do padrão JWT. O sub precisa ser texto, por isso o str.

Leitura linha a linha

Conferir a pulseira

backend/seguranca.py · depois do criar_token
def ler_token(token: str):
    try:
        dados = jwt.decode(token, configuracao["chave_do_token"], algorithms=["HS256"])
    except jwt.InvalidTokenError:          # lacre falso, ou pulseira vencida
        return None
    return int(dados["sub"])                # o id de quem fez a requisição
O decode confere o lacre e a validade antes de devolver. Se alguém mudar uma letra do conteúdo, a assinatura não bate.

Recapitulando

O que fica da aula 8

  • Senha não se guarda. Guarda-se o hash, que confere mas não volta.
  • O argon2 é lento de propósito e usa sal: a mesma senha, digitais diferentes.
  • O token é a pulseira: qualquer um lê, ninguém falsifica sem a chave do .env.

  • Quem é o dono vem do token. O corpo da requisição qualquer um escreve.
