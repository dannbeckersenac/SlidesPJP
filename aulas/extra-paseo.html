O fluxo de uma tarefa

Do pedido ao commit

  1. Você pede uma funcionalidade ao Master.
  2. O Master planeja: escreve o plano, o esqueleto das funções e os testes.
  3. Você aprova o plano, ou pede ajuste.
  4. O Executor implementa, só nos arquivos que o plano libera.
  5. O Master confere: roda os testes e olha o que mudou. Até duas rodadas de ajuste.
  6. Você valida no /docs e faz o commit.

É o fluxo de uma empresa: arquitetura, contrato, teste, implementação, revisão e commit. A ferramenta muda, o fluxo fica.

Python que faltava

O teste vem antes do código

um teste com pytest · o Master escreve, o Executor não pode mexer
def test_cadastrar_item():
    item = cadastrar("Arroz", 2)
    assert item["nome"] == "Arroz"   # assert: confira que isto é verdade
    assert item["quantidade"] == 2 # se não for, o teste falha
  1. O Master escreve o teste, e ele falha: a função cadastrar ainda está vazia.
  2. O Executor escreve a função até o python -m pytest mostrar passed.
  3. Se o Executor mexer no teste, o Master percebe no diff e recusa.

Antes de instalar

Grátis tem preço

Modelo gratuito pode usar o que você manda para treinar. Nada de senha, chave de API ou dado pessoal nos projetos feitos com ele.
  1. Hoje o projeto é de treino, uma lista de compras. O da cartilha segue com o REGRAS.md dele.
  2. O Codex grátis tem limite de uso. Se acabar no meio, siga com tarefas menores ou escreva você.

  4. Um Executor por vez. A máquina e a cota agradecem.

O kickoff

Leia antes de dizer ok

O Master devolve a arquitetura em até dez linhas. Ela é sua a partir do ok.

  1. As pastas fazem sentido? Rota, serviço e repositório, como na aula 4?
  2. As dependências são só fastapi[standard] e pytest?
  3. Nada de banco, login ou async def?
  4. Tudo certo: responda ok. Ele cria o AGENTS.md, o .docs/ e as pastas.
  5. Faça o commit inicial e o push. No GitHub aparecem o AGENTS.md e o .docs/.

Recapitulando

O que fica do extra

  • Modelo gratuito acerta tarefa pequena. A decisão fica com o Master, e a aprovação com você.
  • O Master escreve o teste antes, e o Executor só termina quando ele passa.
  • Plano com a lista de arquivos permitidos: o que não está lá, o Executor não toca.
  • Modelo free pode treinar com o que você manda. Nada de senha nem dado pessoal.
  • Quem revisa, testa e faz o commit é você. O código é seu.

Depois: o mesmo fluxo serve para qualquer projeto. O da cartilha continua seguindo o REGRAS.md dele.
