Python que faltava

Perguntando o tipo de um valor

Para conferir na mão, você precisa saber se "pizza" é número. A função isinstance(valor, tipo) responde True ou False.

A tentativa óbvia

Validar na mão

backend/rotas/pedidos.py
@router.post("")
def criar_pedido(dados: dict):
    if "cliente" not in dados or dados["cliente"] == "":
        raise HTTPException(status_code=422, detail="cliente vazio")
    if not isinstance(dados["item_id"], int):
        raise HTTPException(status_code=422, detail="item_id não é número")
    # falta quantidade, falta observação, e tudo isso em cada rota
Funciona, e cansa: seis linhas para dois campos. E ainda tem buraco: se o item_id nem vier, a API devolve 500.

A virada

Descrever em vez de conferir

Conferindo campo a campo
if "cliente" not in dados:
    raise ...
if dados["cliente"] == "":
    raise ...
if not isinstance(
    dados["quantidade"], int):
    raise ...
if dados["quantidade"] <= 0:
    raise ...
Declarando como o dado é
class PedidoCriar(BaseModel):
    cliente: str = Field(min_length=2)
    item_id: int
    quantidade: int = Field(gt=0)
    observacao: str | None = None

Quatro linhas descrevem o que os if conferiam, e a segunda versão ainda aparece no /docs.

Conceito

Pydantic: o formato como código

Um BaseModel é uma classe que descreve o formato de um dado. O FastAPI usa essa descrição para três coisas ao mesmo tempo, sem você pedir:

1
ConverteTransforma o JSON que chegou em objeto Python já tipado.
2
ValidaRecusa o que não bate com a descrição, antes da sua função rodar.
3
DocumentaPublica o formato exato no /docs, campo por campo.

Não precisa instalar nada: o Pydantic veio junto com o fastapi[standard] da aula 1.

Conceito · linha a linha

Lendo um esquema

backend/esquemas/pedido.py · from pydantic import BaseModel, Field
class PedidoCriar(BaseModel):          # herda os poderes do Pydantic
    cliente: str = Field(min_length=2)  # texto, 2 letras no mínimo
    item_id: int                        # inteiro, obrigatório
    quantidade: int = Field(gt=0)       # inteiro maior que zero
    observacao: str | None = None       # opcional: se não vier, vale None
Cada linha é nome: tipo. Sem =, o campo é obrigatório. Com = None, ele é opcional.

Repare no que falta: não tem __init__ nem self. O Pydantic monta isso sozinho a partir da lista de campos.

Referência

As restrições do Field

RestriçãoQuer dizerExemplo
min_lengthtamanho mínimo do textomin_length=2: "Al" passa, "A" não
max_lengthtamanho máximo do textomax_length=200
gtmaior quegt=0: 1 passa, 0 não
gemaior ou igualge=0: 0 passa, -1 não
lemenor ou igualle=10: 10 passa, 11 não

As siglas vêm do inglês: greater than, greater or equal, less or equal. As duas primeiras linhas valem para texto, as outras para número.

Boa prática

O que entra não é o que sai

CampoEntrada e saída
cliente, item_id, quantidadeo cliente envia, e volta na resposta
idsó sai, porque quem gera é o servidor
criado_em, statussó sai, porque o cliente não escolhe
custo_do_pratonunca sai, é conta do restaurante
Usar o mesmo esquema para entrada e saída é deixar o cliente escolher o próprio id, ou ver dado interno do restaurante. Na aula 13 isso vira falha de segurança de verdade.

O obstáculo final

"Mas no /docs funcionava!"

O erro do passo anterior não fala de pedido nenhum:

console do navegador
Access to fetch at 'http://127.0.0.1:8000/itens' from origin
'http://localhost:5173' has been blocked by CORS policy

A API está certa. Quem bloqueia é o navegador: por padrão, uma página de um endereço não pode ler dados de outro. O servidor precisa autorizar esse endereço.

Mão na massa · passo 6 de 6

Autorizando o seu front

backend/main.py · from fastapi.middleware.cors import CORSMiddleware
app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173"],
    allow_methods=["*"], allow_headers=["*"],
)
  1. Descubra o endereço exato do seu front. O npm run dev imprime ele no terminal.
  2. No main.py, logo depois de app = FastAPI(), registre o middleware com só esse endereço.
  3. Recarregue o React. O erro do console some e a lista aparece na tela.
Nunca allow_origins=["*"]: isso libera a sua API para o mundo inteiro.

Recapitulando

O que fica da aula 3

  • Validar na mão com if e isinstance funciona, e não escala.
  • Um esquema Pydantic descreve o dado uma vez e entrega conversão, validação e documentação.
  • O 422 diz qual campo falhou e por quê, todos de uma vez.
  • Entrada e saída são esquemas diferentes. O cliente não define id nem vê dado interno.
  • O CORS é proteção do navegador. Autorize o seu front, nunca o mundo inteiro.
