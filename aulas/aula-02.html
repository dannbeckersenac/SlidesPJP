A dor de hoje

O front precisa saber o que pedir

Você entregou o CONTRATO.md com quatro seções. Hoje duas delas viram API: os dados que a tela mostra e as ações que o usuário dispara. Só que "ver a lista" e "finalizar o pedido" não são endereços. O navegador não entende português.

Sem uma convenção, cada um inventaria a sua: /pegarCardapio, /listaDeItens, /menu2. REST é a convenção que o mercado já combinou.

Antes do REST, o HTTP · analogia

Uma requisição é um formulário

Pense no requerimento de uma repartição. Os campos são fixos, e por isso qualquer atendente sabe o que fazer com ele.

No requerimentoNa requisição HTTP
O setor para onde ele vaiO caminho: /itens/3
"Marque uma opção: consultar, incluir, alterar, cancelar"O método: GET, POST, PUT, DELETE
Os dados de quem está pedindoOs cabeçalhos
Os documentos anexadosO corpo, em JSON
O carimbo na volta: deferido ou indeferidoO código de status: 200, 404

Um pouco de história

O HTTP nasceu para buscar páginas

Fazer um sistema conversar com outro veio depois. E o REST não foi a primeira tentativa.

1991 · HTTPA web nasce. O navegador pede uma página, o servidor entrega.
→
1998 · SOAPEmpresas querem integrar sistemas. A mensagem vira um envelope XML.
→
2000 · RESTRoy Fielding, um dos autores do HTTP, descreve o estilo da web na tese de doutorado.
→
HojeQuase toda API pública é REST com JSON.

Um pouco de história

O mesmo pedido, nos dois estilos

SOAP · buscar o item 3
POST /CardapioService HTTP/1.1

<soap:Envelope xmlns:soap="...">
  <soap:Body>
    <ObterItem>
      <id>3</id>
    </ObterItem>
  </soap:Body>
</soap:Envelope>
REST · buscar o item 3
GET /itens/3 HTTP/1.1
No SOAP, todo pedido vai por POST para o mesmo endereço, e a ação vai escrita dentro do XML. No REST, o método e o caminho já dizem tudo.

Um pouco de história

As diferenças que importam

SOAPREST
MensagemXML, dentro de um envelopeJSON, na prática
Endereçoum só para o serviço inteiroum para cada recurso
Métodoquase sempre POSTo que combina com a ação
ContratoWSDL, escrito antes do códigoOpenAPI, o seu /docs

Repare no contrato: o SOAP exigia um arquivo WSDL escrito à mão. No FastAPI, o /docs faz esse papel e sai do seu código.

Um pouco de história

Ele ficou onde o contrato rígido compensa o peso do XML.

2

3

Conceito

REST em quatro ideias

O Fielding olhou para a web que já funcionava e resumiu por que ela funcionava.

1
RecursoCada coisa que o sistema guarda tem endereço próprio: /itens/3.
2
Poucos verbosOs mesmos métodos servem para qualquer recurso.
3
RepresentaçãoO que viaja é uma descrição do recurso, hoje em JSON.
4
Sem memóriaCada requisição chega completa. O servidor não lembra da anterior.

De volta à repartição: /pedidos é a gaveta do arquivo e /pedidos/7 é a pasta 7. Em qualquer gaveta você faz as mesmas quatro coisas.

Conceito · a regra prática

O caminho é substantivo, o método é verbo

Verbo no caminho
GET  /pegarCardapio
GET  /verItem?id=3
POST /criarPedido
POST /cancelarPedido/7
Substantivo no caminho
GET    /itens
GET    /itens/3
POST   /pedidos
DELETE /pedidos/7
A ideia do REST em uma frase: o caminho diz de qual coisa você está falando, o método diz o que você quer fazer com ela.

Consequência prática: caminho no plural e em minúsculas, como /itens e /pedidos. Nunca um verbo.

Referência

O que cada método promete

MétodoPara quêAltera dados?Leva corpo?
GETlernãonão
POSTcriarsimsim, o recurso novo
PUTsubstituirsimsim, a versão nova
DELETEremoversimnão
GET nunca altera nada. Navegador, buscador e cache repetem GET à vontade. Uma rota GET que apaga dado vai apagar sem ninguém pedir.

Na repartição: GET é pedir para ver a pasta. Pode pedir cem vezes, o arquivo continua igual.

Referência

Os quatro métodos do dia a dia

Ação no cardápio digitalMétodo e caminho
Listar os itens do cardápioGET /itens
Ver um item específicoGET /itens/3
Criar um pedido novoPOST /pedidos
Alterar um pedido existentePUT /pedidos/7
Cancelar um pedidoDELETE /pedidos/7

Note o padrão: o mesmo caminho /pedidos/7 serve para ver, alterar e apagar. Quem decide é o método.

Conceito

O primeiro dígito diz de quem é a culpa

FamíliaQuer dizerNo balcão da repartição
2xxdeu certo"Deferido. Aqui está."
3xxestá em outro lugar"Isso agora é no outro prédio."
4xxquem pediu errou"O seu formulário veio errado."
5xxquem responde errou"O sistema caiu aqui dentro."

Existe ainda a família 1xx, só informativa. Você quase não vai cruzar com ela.

Referência

Os códigos que importam agora

CódigoO que ele comunica
200 OKDeu certo, aqui está o que você pediu
201 CreatedCriei o recurso que você mandou
404 Not FoundEsse item não existe
422 UnprocessableVocê mandou dado inválido (a aula 3 é sobre isso)
500 Server ErrorQuebrou do meu lado, e a culpa é sua, desenvolvedor
O front toma decisão pelo status: 200 renderiza a lista, 404 mostra "não encontrado", 500 mostra erro genérico. Devolver 200 com uma mensagem de erro dentro quebra o front.

Mão na massa · passo 2 de 4

Um item específico

backend/main.py · from fastapi import HTTPException
@app.get("/itens/{item_id}")
def obter_item(item_id: int):
    for item in cardapio:
        if item["id"] == item_id:
            return item
    raise HTTPException(status_code=404, detail="Item não encontrado")
  1. Escreva o caminho com {item_id} entre chaves e repita o mesmo nome no parâmetro da função.
  2. Anote o tipo: item_id: int. Só isso já faz o FastAPI converter e validar antes da função rodar.
  3. Teste os três casos: /itens/1 devolve o item, /itens/99 devolve 404, /itens/abc devolve 422.

Conceito

Filtrando sem criar rota nova

Uma rota por filtro
GET /itens/bebidas
GET /itens/pratos
GET /itens/sobremesas
# e a próxima categoria?
Um parâmetro de consulta
GET /itens?categoria=bebida
GET /itens?categoria=prato
GET /itens?categoria=sobremesa
GET /itens   # sem filtro, vem tudo
Tudo que vem depois do ? é consulta, no formato nome=valor. O caminho continua /itens, e uma rota só atende todos os filtros.

Para não confundir: o parâmetro de caminho (/itens/3) aponta um item. O de consulta (?categoria=bebida) filtra a lista.

Mão na massa · passo 3 de 4

O filtro com um laço

@app.get("/itens")
def listar_itens(categoria: str | None = None):  # texto ou nada; padrão None
    if categoria is None:                         # não veio ?categoria= na URL
        return cardapio
    filtrados = []
    for item in cardapio:
        if item["categoria"] == categoria:
            filtrados.append(item)
    return filtrados
  1. No main.py, acrescente à rota GET /itens o parâmetro categoria, com padrão None.
  2. Abaixo do if, monte a lista filtrados com o laço, como no código.
  3. Abra /itens?categoria=bebida: só as bebidas aparecem. Sem o ?, volta tudo.

Python que faltava · o atalho

O mesmo filtro, em compreensão de lista

Com laço
filtrados = []
for item in cardapio:
    if item["categoria"] == categoria:
        filtrados.append(item)
Com compreensão de lista
filtrados = [item
    for item in cardapio
    if item["categoria"] == categoria]
  1. [item, no começo: o que vai para dentro da lista nova.
  2. for item in cardapio: o mesmo laço da esquerda.
  3. if ...: o mesmo filtro. Só entra o item que passar.
O resultado é igual, e a IA costuma escrever a da direita numa linha só. Entregue a que você sabe explicar.

Mão na massa · passo 4 de 4

O main.py não pode virar o sistema inteiro

Duas rotas cabem num arquivo. Vinte não.

  1. Crie a pasta backend/rotas/ com dois arquivos: itens.py e pedidos.py.
  2. Em cada um, use router = APIRouter() no lugar de app, e @router.get no lugar de @app.get.
  3. Tire o prefixo dos caminhos: ele passa a ser declarado no main.py.
  4. Registre os dois no main.py e confira o /docs: as rotas agora aparecem agrupadas por tag.
backend/main.py
from rotas import itens, pedidos

app.include_router(itens.router, prefix="/itens", tags=["Cardápio"])
app.include_router(pedidos.router, prefix="/pedidos", tags=["Pedidos"])

Recapitulando

O que fica da aula 2

  • O caminho diz de qual coisa você fala; o método diz o que fazer com ela.
  • O status é o que o front usa para decidir o que mostrar. Não devolva 200 para erro.
  • Parâmetro de caminho identifica; parâmetro de consulta filtra.
  • Escrever o tipo já ganha conversão e validação de graça.
  • O /docs é o contrato, e ele se atualiza sozinho porque nasce do código.
