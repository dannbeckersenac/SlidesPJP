A dor de hoje

Derrube a API e olhe a tela

o fetch da aula 3, no componente da sua tela
const [itens, setItens] = useState([]);
useEffect(() => {
  fetch("http://127.0.0.1:8000/itens")
    .then((resposta) => resposta.json())

  1. Com a tela aberta no navegador, pare o fastapi dev no terminal com Ctrl+C.
  2. Recarregue a página do React.
  3. Olhe a tela: vazia, sem aviso nenhum. O erro existe, mas só no console, que o usuário nunca abre.

Onde paramos

Quatro problemas, uma tela vazia

O que aconteceuO que a tela mostra
a API está demorandonada
a API caiunada
o endereço está errado e voltou 404nada
a lista realmente está vazianada
O usuário não sabe se espera, se tenta de novo ou se desiste. Hoje a tela passa a dizer qual das quatro está acontecendo.

Conceito

Toda tela que busca dados vive em três estados

Como o garçom da aula 4: ou o prato ainda não saiu, ou deu problema, ou chegou.

1
CarregandoO pedido saiu e ainda não voltou. A tela avisa que está buscando.
2
ErroVoltou errado, ou nem voltou. A tela diz o que houve, em português.
3
ProntoVoltou certo. A tela mostra os dados, ou avisa que a lista está vazia.

No código são três variáveis: os dados, se ainda está carregando e qual foi o erro.

Conceito

O fetch só reclama quando nem houve resposta

SituaçãoO que o fetch fazCai no
a API está fora do arrejeita a promessa.catch
a API respondeu 404 ou 500resolve, com ok falso.then
a API respondeu 200 ou 201resolve, com ok verdadeiro.then
Um 404 é uma resposta, então o fetch não vê problema nenhum. Quem decide que aquilo é erro é você, olhando o resposta.ok.

JavaScript que faltava

O throw pula direto para o catch

console do navegador · se ele recusar a colagem, digite allow pasting
fetch("/nao-existe")
  .then((resposta) => {
    if (!resposta.ok) throw new Error("a API respondeu " + resposta.status);
    return resposta.json();
  })
  .then((dados) => console.log("chegou:", dados))
  .catch((problema) => console.log("caiu no catch:", problema.message));
  1. Com a API no ar, abra o /docs, aperte F12 e vá na aba Console.
  2. Cole o código e aperte Enter. Aparece caiu no catch: a API respondeu 404.
  3. Troque /nao-existe por uma rota da sua API e rode de novo. Aparece chegou: com os dados.

Mão na massa · passo 2 de 4

O fetch com os três desfechos

useEffect(() => {
  fetch("http://127.0.0.1:8000/itens")
    .then((resposta) => {
      if (!resposta.ok) throw new Error("a API respondeu " + resposta.status);
      return resposta.json();
    })
    .then((dados) => { setItens(dados); setCarregando(false); })
    .catch((problema) => { setErro(problema.message); setCarregando(false); });
}, []);
  1. Troque o useEffect antigo por este, e /itens pelo caminho da sua API.
  2. Repare nos dois lugares que desligam o carregando: quando deu certo e quando deu errado.
  3. Salve. O terminal do npm run dev não pode mostrar erro.

JavaScript que faltava

O fetch que envia dados

as opções de um POST · pedido é o objeto com os campos do formulário
const opcoes = {
  method: "POST",                                  // o método da aula 2
  headers: { "Content-Type": "application/json" }, // avisa que o corpo é JSON
  body: JSON.stringify(pedido),                    // o objeto vira texto
};
Sem o Content-Type, o FastAPI recebe o corpo como texto comum e responde 422, mesmo com todos os campos certos.

JSON.stringify transforma o objeto no texto que viaja na requisição. O resposta.json() faz o caminho de volta.

Mão na massa · passo 4 de 4

O formulário que cria

na função que o botão de enviar chama, logo depois das opcoes
fetch("http://127.0.0.1:8000/pedidos", opcoes)
  .then((resposta) => {
    if (resposta.status === 422) throw new Error("confira os campos do formulário");
    if (!resposta.ok) throw new Error("a API respondeu " + resposta.status);
    return resposta.json();
  })
  .then((criado) => setMensagem("Pedido " + criado.id + " criado"))
  .catch((problema) => setMensagem("Não foi: " + problema.message));
  1. No formulário da sua tela, crie um estado mensagem e mostre ele abaixo do botão.
  2. Na função do botão, monte as opcoes e chame o fetch acima.
  3. Mande um campo inválido: aparece "confira os campos". Mande tudo certo: aparece o número criado.

O sorteio

Cinco cartilhas, dez pessoas

  1. Cada cartilha é um negócio com um problema, uma pessoa que usa e alguém que toca o negócio.
  2. Cada cartilha sai para dois alunos, que trabalham separados.
  3. Vocês não combinam nada: marca, cores, telas e rotas são de cada um.
  4. Depois da entrega, cada um olha o que o outro fez. Na apresentação, você explica por que fez diferente.
  5. Eu também tirei uma cartilha, e resolvo ela no quadro junto com vocês.
As cinco têm o mesmo tamanho de problema. Ninguém tirou a cartilha fácil.

A régua · o que veio da UC5

Briefing, marca e styleguide

  1. Briefing: a dor com as suas palavras, os dois perfis, as jornadas e o que fica de fora.
  2. Marca: o nome, o logo colorido e em uma cor só, e três linhas sobre por que ele é assim.
  3. Styleguide: paleta com contraste AA, tipografia e os componentes base.
  4. A ponte com o código: as cores e as fontes do styleguide são as mesmas do CSS.

A régua · o que é desta UC

Front e back

  1. Front: as quatro telas, e as da pessoa impecáveis no celular.
  2. Três estados: toda tela que busca dados mostra carregando, erro e vazio.
  3. Back: as cinco capacidades, em rotas, serviços, repositórios e esquemas.
  4. A regra: no serviço, e a recusa aparece na tela como mensagem.
  5. O que não vai: banco, login e senha. Os dados ficam em memória, como na aula 4.
