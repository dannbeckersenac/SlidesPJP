A dor de hoje

Onde os dados da tela moram hoje

exemplo do professor · frontend/src/dados/cardapio.js
export const cardapio = [
  { id: 1, nome: "Pizza Marguerita", preco: 39.90 },
  { id: 2, nome: "Lasanha Bolonhesa", preco: 42.00 },
  { id: 3, nome: "Suco de Laranja",   preco: 12.50 }

A sua tela tem um arquivo assim, com os dados da sua persona. Ela está pronta e os dados são mentira: mudar um preço exige alterar o código e publicar de novo.

Conceito

Back-end é quem responde

O front-end desenha e pergunta. O back-end guarda, decide e responde. Entre os dois existe um combinado de quem pede o quê e recebe o quê, e esse combinado tem nome: a API.

Ideia central: a tela deixa de ser dona dos dados e passa a ser apenas quem os apresenta.

Repare: nada do que você fez na UC5 será jogado fora. O React continua igual. Só muda de onde ele busca a lista.

Como funciona

O caminho de um pedido

A tela pedeO React faz uma requisição HTTP para um endereço da API
→
A API respondeO servidor executa a função da rota e devolve JSON
→
A tela mostraO React recebe o JSON e renderiza o cardápio

Os três passos acontecem em milissegundos e são independentes. Dá para testar a API sem abrir a tela, e é exatamente isso que vamos fazer hoje.

Mão na massa · passo 1 de 4

Organizando o repositório

Front e back convivem no mesmo repositório, em pastas separadas. Cada um roda por conta própria.

  1. Na raiz do seu repositório, crie a pasta backend/. É onde a API vai morar.
  2. Mova o projeto React da UC5 inteiro para uma pasta frontend/, sem alterar nada dentro dele.
  3. Crie um .gitignore na raiz com três linhas: venv/, node_modules/ e .env.
  4. Rode git status. Se aparecer alguma dessas três pastas na lista, o .gitignore está no lugar errado.
Segredo e dependência nunca vão para o Git. Essa regra vale da aula 1 até a entrega final.

Mão na massa · passo 2 de 4

Montando o ambiente

terminal · dentro de backend/
python -m venv venv
venv\Scripts\activate        # Windows
# source venv/bin/activate    # Linux e Mac

pip install "fastapi[standard]"
  1. Abra o terminal dentro de backend/. Fora dela, o venv nasce no lugar errado.
  2. Crie o ambiente virtual e ative. O nome (venv) passa a aparecer no início da linha.
  3. Instale o FastAPI. Se o (venv) não estiver ali, você acabou de instalar na máquina toda.
  4. O venv guarda as versões só deste projeto. Sem ele, instalar algo aqui quebra outro projeto da sua máquina.

Mão na massa · passo 3 de 4

A menor API que existe

backend/main.py
from fastapi import FastAPI

app = FastAPI(title="Cardápio Digital")

@app.get("/health")
def health():
    return {"status": "ok"}
  1. Crie backend/main.py e digite as seis linhas. Digite, não cole.
  2. O decorador @app.get("/health") diz: quando pedirem este endereço com GET, rode a função.
  3. O dicionário devolvido pela função vira JSON sozinho. Você não converte nada.

Mão na massa · passo 4 de 4

Subindo o servidor

terminal · dentro de backend/, com o venv ativo
fastapi dev main.py

#  Server started at http://127.0.0.1:8000
#  Documentation at http://127.0.0.1:8000/docs
  1. Rode o comando. O terminal fica ocupado, e é assim mesmo: o servidor está no ar.
  2. Abra http://127.0.0.1:8000/health. Você deve ver {"status":"ok"}.
  3. Abra http://127.0.0.1:8000/docs. A rota /health está listada lá.
Ninguém escreveu a página do /docs: o FastAPI gerou tudo a partir do seu código.

O combinado da turma

A IA pode escrever. Você tem que explicar.

Vocês usam IA desde a UC5 e vão continuar usando aqui, todo dia, do primeiro commit até a entrega final. A partir de agora vale uma regra, e ela vale nas três avaliações:

1
Pode gerarUse a IA para escrever, refatorar e documentar à vontade.
2
Tem que lerCódigo que entra no repositório é código que você entendeu linha a linha.
3
Vai explicarToda entrega tem arguição individual: eu aponto uma linha, você justifica.

Traduzindo: não existe "a IA que fez". Existe o que você entregou.

Conceito

Dois arquivos guiam a IA

CONTEXT.md · você escreve
Back-end FastAPI em `backend/`.
Front React da UC5 em `frontend/`.
Rodar: `fastapi dev main.py`.
Código e respostas em português.
Persona: a sua, em uma linha.
REGRAS.md · eu entrego pronto
Pode usar: @app.get, def, dict,
lista em memória, /docs.
Não use: banco, ORM, Pydantic,
APIRouter, login, async def.
Se precisar disso, avise antes.
Código sempre comentado.
baixar o REGRAS_AULA1.md

Por que o segundo: sem limite, ela resolve a aula 1 com banco de dados e você entrega o que não sabe explicar.

Mão na massa

Peça o rascunho, entregue a versão

  1. Na raiz do seu repositório, peça à IA: leia as pastas e escreva um CONTEXT.md com a stack, a estrutura e como rodar.
  2. Leia linha a linha e apague o que não é verdade. Ela chuta versão, chuta pasta, chuta framework.
  3. Escreva à mão o que ela não tem como saber: quem é a sua persona e qual é a dor dela.
  4. Commite o arquivo. Ele é parte do projeto, igual ao código.
  5. Abra um chat novo e peça algo pequeno. Se ela acertar a pasta e o framework, o arquivo está bom.

Repare na ordem: a IA escreve o rascunho. Quem assina o arquivo é você.

Recapitulando

O que fica da aula 1

  • A tela da UC5 tinha dados chumbados no código, e é isso que o back-end vem resolver.
  • Front e back convivem no mesmo repositório, em pastas separadas, cada um com seu ambiente.
  • Uma rota é uma função com um decorador. O que ela devolve vira JSON.
  • O /docs nasce sozinho a partir do código, e é ele que o front vai ler.
  • O combinado: a IA pode escrever, você tem que explicar.
  • O CONTEXT.md apresenta o projeto à IA. O REGRAS.md diz até onde ela pode ir hoje.
