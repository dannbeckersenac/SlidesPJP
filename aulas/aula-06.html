def salvar(tarefa: dict):
    conexao = abrir_conexao()           # host, usuário, senha e banco
    cursor = conexao.cursor()
    cursor.execute(
        "INSERT INTO tarefas (titulo, descricao, prazo, situacao,"
        " itens_feitos, solicitante_id) VALUES (%s, %s, %s, %s, %s, %s)",
        (tarefa["titulo"], tarefa["descricao"], tarefa["prazo"],
         tarefa["situacao"], tarefa["itens_feitos"], tarefa["solicitante_id"]))
    conexao.commit()
    tarefa["id"] = cursor.lastrowid     # o número que o banco gerou
    conexao.close()
    return tarefa

def listar():
    conexao = abrir_conexao()
    cursor = conexao.cursor()
    cursor.execute("SELECT id, titulo, descricao, prazo, situacao,"
                   " itens_feitos, solicitante_id FROM tarefas")

    conexao.close()
    return tarefas

A segunda dor de hoje

Onde dói

O que você viuO que isso custa
as colunas escritas três vezesCREATE, INSERT e SELECT têm que concordar para sempre
a linha chega como tuplatrocou a ordem do SELECT, o título vira descrição, sem erro
o SQL é um textoerro de digitação só aparece quando a rota roda, como 500
abrir e fechar a conexãorepetido em toda função do repositório
Você fala Python e o banco fala SQL. Até agora, o tradutor era você.

Conceito

ORM: uma classe vira uma tabela

ORM é Object-Relational Mapping. Você escreve a classe, e ele escreve o SQL.

O seu códigoUm objeto Tarefa, com título, prazo e situação.
→
O SQLAlchemyO tradutor: faz do objeto um INSERT, e da linha um objeto.
→
O MySQLRecebe o mesmo SQL de sempre. Nem sabe que foi o Python.

O SQL não sumiu. Ele só deixou de ser escrito por você.

Você escreve, em Python

Classe vira tabela, atributo vira coluna, objeto vira linha. É o mesmo INSERT que você escreveu à mão.

Conceito

As quatro peças do SQLAlchemy

1
EngineSabe onde o banco está e abre as conexões. Um só no projeto.
2
SessãoUma conversa com o banco: abre, pede, grava e fecha.
3
BaseA classe mãe. Todo modelo herda dela, como o esquema herda de BaseModel.
4
ModeloUma classe por tabela, um atributo por coluna.
Modelo não é esquema. O esquema, em esquemas/, confere o que chega na requisição. O modelo, em modelos/, é a tabela.

Onde paramos

A conversa fechou antes da mudança

exemplo do professor · o caminho da tarefa, do repositório até a regra
# repositorios/tarefa.py
def buscar_por_id(tarefa_id: int):
    sessao = Sessao()                   # abre a conversa
    tarefa = sessao.get(Tarefa, tarefa_id)
    sessao.close()                       # e fecha antes de devolver
    return tarefa

# servicos/item.py, a regra
    tarefa.itens_feitos += 1              # muda o objeto, com a conversa já fechada
    tarefa.situacao = "em andamento"       # e ninguém faz o commit

Cada função do repositório tem a sua conversa. Quem muda a tarefa não fala com nenhuma delas.

Conceito

Uma conversa por requisição

A sessão abre quando a requisição chega e fecha quando a resposta sai. No meio, as três camadas usam a mesma.

Chega a requisiçãoO FastAPI abre uma sessão.
→
Rota, serviço, repositórioRecebem a mesma sessão, de mão em mão.
→
Sai a respostaO FastAPI fecha a sessão.

Quem entrega a sessão é o Depends, o mesmo da aula 4. Para escrever essa função, faltam duas peças de Python.

Python que faltava

with: abre, usa e fecha sozinho

no terminal, com python
with open("teste.txt", "w") as arquivo:   # abre e dá um nome
    arquivo.write("oi")                 # usa dentro do bloco

print(arquivo.closed)                    # True: fechou na saída do bloco
  1. No terminal, digite python e cole o código acima.
  2. A última linha mostra True. Ninguém chamou close().
O with fecha na saída do bloco, mesmo se der erro lá dentro. A sessão do SQLAlchemy funciona igual.

Python que faltava

yield: entrega e espera

no terminal, com python
def conversa():
    print("abre")
    yield "sessão"          # entrega o valor e para aqui
    print("fecha")            # só roda quando quem recebeu termina

for valor in conversa():
    print("usa a", valor)
  1. Cole no mesmo terminal e aperte Enter duas vezes.
  2. Aparecem três linhas, nesta ordem: abre, usa a sessão, fecha.

O return entrega e acaba. O yield entrega, espera o outro lado usar e depois continua.

A função que entrega a sessão

def obter_sessao():
    with Sessao() as sessao:   # fecha sozinho, mesmo com erro
        yield sessao             # entrega para a rota e espera a resposta sair
  1. No banco.py, acrescente a função acima, depois da class Base.
  2. No terminal do backend/, rode python -c "import banco".
  3. Nenhuma mensagem é o resultado certo.

É a mesma conversa do slide anterior. No lugar do for, quem usa a sessão é a rota.

Referência

CRUD: as quatro operações na sessão

OperaçãoVocê escreveO banco recebe
Criarsessao.add(obj) e commit()INSERT
Lersessao.get ou sessao.scalars(select())SELECT
Atualizarmuda o atributo e commit()UPDATE
Apagarsessao.delete(obj) e commit()DELETE
O UPDATE não tem comando próprio. A sessão anota o que mudou no objeto e grava no commit.

Apagar só se a sua cartilha pedir. Rota que ninguém usa é rota que você vai ter que explicar.

Leitura linha a linha

O item aponta para a tarefa

exemplo do professor · backend/modelos/item.py
from sqlalchemy import Column, Integer, String, Date, ForeignKey
from banco import Base
class ItemChecklist(Base):
    __tablename__ = "itens_checklist"
    id = Column(Integer, primary_key=True)
    tipo = Column(String(20), nullable=False)
    descricao = Column(String(200), nullable=False)
    data = Column(Date, nullable=False)
    # FOREIGN KEY: o banco só aceita o id de uma tarefa que existe
    tarefa_id = Column(Integer, ForeignKey("tarefas.id"), nullable=False)

"tarefas.id" é tabela ponto coluna, com o nome do __tablename__, não o da classe.

A ForeignKey é a coluna no banco. O relationship é o atalho no Python: não cria coluna nenhuma.

Conceito

Dois commits, duas chances de dar metade

Dois commits
# commit 1: grava a tarefa
repositorio_tarefa.atualizar(sessao, tarefa)
# commit 2: grava o item. se falhar,
# a tarefa fica sem o item que a mudou
repositorio.salvar(sessao, dados)
Um commit
# a regra muda a tarefa e não grava
repositorio.salvar(sessao, dados)
# um commit: o item e a tarefa,
# juntos, ou nenhum dos dois
Transação é o que vai junto para o banco. O commit grava tudo o que a sessão anotou. O rollback descarta tudo.

Conceito

Migration: o commit do banco

O Git guarda cada mudança do código. A migration guarda cada mudança das tabelas, em ordem.

1
O arquivoUm .py por mudança, em migracoes/versions/. Vai para o Git.
2
A versãoUma tabela alembic_version diz em que mudança o banco está.
3
O upgradeRoda só as mudanças que o banco ainda não tem.

Quem faz isso é o Alembic, escrito pelo mesmo autor do SQLAlchemy. Ele compara os modelos com o banco e escreve a mudança.

Recapitulando

O que fica da aula 6

  • Lista em memória morre com o servidor. O ORM traduz: uma classe é uma tabela.
  • Uma sessão por requisição, entregue pelo Depends, de mão em mão pelas três camadas.
  • O UPDATE é mudar o atributo e dar commit. Um commit só grava a regra inteira, ou nada.
  • A ForeignKey é a coluna; o relationship é o atalho; o banco filtra, ordena e pagina.
  • O create_all não altera tabela. A migration guarda cada mudança, em ordem.
