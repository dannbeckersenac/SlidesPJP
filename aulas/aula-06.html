A segunda dor de hoje

A tabela, escrita à mão

no MySQL do professor · o SQL do curso de Python
CREATE TABLE tarefas (
  id INT PRIMARY KEY AUTO_INCREMENT,   -- o banco numera sozinho
  titulo VARCHAR(100) NOT NULL,        -- texto de até 100, obrigatório
  descricao VARCHAR(500) NOT NULL,
  prazo DATE NOT NULL,                 -- só o dia, sem hora
  situacao VARCHAR(20) NOT NULL,
  itens_feitos INT NOT NULL,
  solicitante_id INT NOT NULL          -- o número de quem pediu
);

Eu rodo, você acompanha. Os tamanhos são os mesmos do Field do esquema. No seu projeto, quem cria a tabela vai ser o Python.

A segunda dor de hoje

Gravar com SQL à mão

exemplo do professor · repositorios/tarefa.py com mysql.connector
def salvar(tarefa: dict):
    conexao = abrir_conexao()           # host, usuário, senha e banco
    cursor = conexao.cursor()
    cursor.execute(
        "INSERT INTO tarefas (titulo, descricao, prazo, situacao,"
        " itens_feitos, solicitante_id) VALUES (%s, %s, %s, %s, %s, %s)",
        (tarefa["titulo"], tarefa["descricao"], tarefa["prazo"],
         tarefa["situacao"], tarefa["itens_feitos"], tarefa["solicitante_id"]))
    conexao.commit()
    tarefa["id"] = cursor.lastrowid     # o número que o banco gerou
    conexao.close()
    return tarefa

A segunda dor de hoje

Ler com SQL à mão

exemplo do professor · repositorios/tarefa.py com mysql.connector
def listar():
    conexao = abrir_conexao()
    cursor = conexao.cursor()
    cursor.execute("SELECT id, titulo, descricao, prazo, situacao,"
                   " itens_feitos, solicitante_id FROM tarefas")
    tarefas = []
    for linha in cursor.fetchall():      # cada linha chega como tupla
        tarefas.append({"id": linha[0], "titulo": linha[1], "descricao": linha[2],
                        "prazo": linha[3], "situacao": linha[4],
                        "itens_feitos": linha[5], "solicitante_id": linha[6]})
    conexao.close()
    return tarefas

A segunda dor de hoje

Onde dói

O que você viuO que isso custa
as colunas escritas três vezesCREATE, INSERT e SELECT têm que concordar para sempre
a linha chega como tuplatrocou a ordem do SELECT, o título vira descrição, sem erro
o SQL é um textoerro de digitação só aparece quando a rota roda, como 500
abrir e fechar a conexãorepetido em toda função do repositório
Você fala Python e o banco fala SQL. Até agora, o tradutor era você.

Conceito

ORM: uma classe vira uma tabela

ORM é Object-Relational Mapping. Você escreve a classe, e ele escreve o SQL.

O seu códigoUm objeto Tarefa, com título, prazo e situação.
→
O SQLAlchemyO tradutor: faz do objeto um INSERT, e da linha um objeto.
→
O MySQLRecebe o mesmo SQL de sempre. Nem sabe que foi o Python.

O SQL não sumiu. Ele só deixou de ser escrito por você.

Conceito

O tradutor, ao vivo

Você escreve, em Python
tarefa = Tarefa(
    titulo="Trocar o toner",
    descricao="Impressora do 2º andar",
    prazo=date(2026, 10, 2),
    situacao="aberta",
    itens_feitos=0, solicitante_id=1,
)
sessao.add(tarefa)
sessao.commit()
O MySQL recebe, em SQL
INSERT INTO tarefas
  (titulo, descricao, prazo,
   situacao, itens_feitos,
   solicitante_id)
VALUES
  ('Trocar o toner',
   'Impressora do 2º andar',
   '2026-10-02', 'aberta', 0, 1);
COMMIT
Classe vira tabela, atributo vira coluna, objeto vira linha. É o mesmo INSERT que você escreveu à mão.

Conceito

As quatro peças do SQLAlchemy

1
EngineSabe onde o banco está e abre as conexões. Um só no projeto.
2
SessãoUma conversa com o banco: abre, pede, grava e fecha.
3
BaseA classe mãe. Todo modelo herda dela, como o esquema herda de BaseModel.
4
ModeloUma classe por tabela, um atributo por coluna.
Modelo não é esquema. O esquema, em esquemas/, confere o que chega na requisição. O modelo, em modelos/, é a tabela.

Leitura linha a linha

A tabela, em Python

exemplo do professor · backend/modelos/tarefa.py
from sqlalchemy import Column, Integer, String, Date
from banco import Base

class Tarefa(Base):                             # herda da Base: vira tabela
    __tablename__ = "tarefas"                    # o nome da tabela no MySQL
    id = Column(Integer, primary_key=True)       # INT PRIMARY KEY AUTO_INCREMENT
    titulo = Column(String(100), nullable=False) # VARCHAR(100) NOT NULL
    descricao = Column(String(500), nullable=False)
    prazo = Column(Date, nullable=False)         # DATE NOT NULL
    situacao = Column(String(20), nullable=False)
    itens_feitos = Column(Integer, nullable=False)
    solicitante_id = Column(Integer, nullable=False)

Você escreveO que acontece no banco

Recapitulando

O que fica da aula 6

  • Lista em memória morre com o servidor. Banco é o que fica.
  • SQL à mão funciona, mas as colunas se repetem e a linha chega como tupla.
  • O ORM traduz: uma classe é uma tabela, um atributo é uma coluna.
  • Engine sabe onde o banco está. A sessão é a conversa: abre, pede, grava e fecha.
  • O repositório troca o corpo e mantém os nomes. O serviço troca colchete por ponto.

Próxima aula: a regra da sua cartilha muda a principal, e o banco não fica sabendo. A sessão passa a atravessar a requisição, e as três tabelas se ligam.
